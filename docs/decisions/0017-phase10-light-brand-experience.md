# ADR-0017 — Phase 10 轻量现代（C / Light Brand）界面基线

- 状态：Accepted（用户已选择视觉方向；交互与无障碍验收仍进行中）
- 日期：2026-11-01（Qual 本机时区）
- 关联项目任务：QUAL-9…QUAL-17，视觉基线 QUAL-11

## 背景

Qual 在 Phase 0–9 已具备 WorkItem、Testing、Evidence、Audit 和 Human/Agent RBAC 等真实业务能力，但现有 UI 较偏工程演示：导航层级单薄，系统运维说明抢占工作台，任务/质量/协作数据关联较弱。

用户从三种视觉方向中明确选定 **C 轻量现代（Light Brand）**。该选择指视觉语言，不等于先前调研中的“C Quality Pulse”功能单一主视图：工作台仍面向跨角色的日常工程工作，质量视图是其组成部分。

## 决策

1. **主题**：日间默认为接近白的柔和暖冷灰底、浅蓝紫辅助面、深色正文、蓝紫主操作；只用颜色表达真实业务语义，并保留易读暗色主题 Tokens。
2. **导航**：Workspace 概览/项目/测试分层；进入 Project 后显示工作项、用例、运行、活动及项目管理入口。管理入口不再与主要工作操作并排争夺注意力。所有原有路由保持兼容。
3. **信息优先级**：工作状态、标题、责任事实、测试状态和相关证据高于技术 ID。保留可以复制/追踪 UUID 与不可变版本；在缺乏主体名称的 API 上不编造人名或 Agent。
4. **真实数据**：页面不预填通过率、项目健康度、Agent 工作负载等演示数值。对分页统计清楚标注「当前已加载」，不将其称为全量统计。
5. **产品安全边界**：Qual 只是管理/归档工具，不执行 Agent/CI/测试；浏览器通过 Human Session/CSRF，Agent 通过受限 MCP/CLI/API，任何浏览器可见按钮都不意味着获得额外权限。
6. **增量交付**：Stage 1 改造设计 Tokens 与 Shell；Stage 2 工作台与看板；Stage 3 任务/审核；Stage 4 测试与证据；Stage 5 浏览器、无障碍、权限回归。按原子提交并保留旧页面能力。

## 取舍

- 参考 C 概念图的氛围和清晰度，不复制图中的假数值、虚构 Agent、不可访问的功能及装饰性仪表盘。
- 不新增后端接口来服务美术效果；缺少指标接口时以真实工作列表、导航入口与明确空态代替模拟统计。
- 不依赖生产级登录改造，本轮不触碰 Principal、PAT、RBAC 与后端状态机。

## 验收门槛

- 原有路由和核心动作可访问，导航响应式；键盘有明确 focus，移动端不遮挡主操作。
- 无权限/未登录状态不显示不可靠的审核结果或假状态。
- TS lint/typecheck/build、适用的 Go 回归、浏览器桌面/小屏操作和视觉对照有真实记录。
- 未做完的登录态测试必须标记 blocked，不能以静态构建替代验收。
